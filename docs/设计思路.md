# 僵尸炮台 · 设计思路

> 类「向僵尸开炮」的竖屏塔防射击 H5 小游戏。玩家用鼠标/触摸控制炮台方向、自动开火抵御成波推进的僵尸，波次间三选一局内强化并触发组合技，通关赚金币做永久养成。

---

## 当前设计基线（2026-08-10）

| 维度 | 当前规模 | 设计约束 |
| --- | --- | --- |
| 敌人生态 | 55 类、18 种行为原型、8 种元素、5 个元素 Boss | 普通敌人维持原始程序绘制；只有 Boss 使用正式 ImageGen 立绘 |
| 元素结算 | 弱点 ×1.55、抗性 ×0.58、免疫 ×0 | 技能、弹药、辅助炮台与伙伴伤害都必须传递真实元素类型 |
| 局内构筑 | 48 技能、29 组合技、过载与终极进化 | 重点不是堆数值，而是形成可感知的清屏方式 |
| 局外配置 | 12 永久强化、14 军械、15 行为装备、6 伙伴协议 | 数据条目必须有运行时效果，禁止“只显示不生效” |
| 核心情绪 | 压力快速堆高，爆发迅速释放 | 用密集尸潮、顿帧、屏震、连锁和范围伤害制造“解压、爽” |

## 一、设计目标

1. **竖屏单手操作**：720×1280 画幅，FIT 缩放自适应；网页鼠标移动控向、安卓触摸拖动控向，松手保持方向。
2. **Boss 正式素材 + 普通敌人程序绘制**：首领与终极技能使用版本化正式 PNG；普通僵尸和精英词缀坚持 `BootScene` Graphics 风格，保证尸潮同屏性能与视觉一致。
3. **短局 + roguelite 成长**：单局 3–5 分钟，波次间选技能、凑组合技；局外金币永久升级，形成「打→养成→打更强」循环。
4. **强打击感**：暴击顿帧、慢动作、连击倍率、屏震、低血量红屏，让每次命中都有反馈。
5. **跨平台一致**：Web（GitHub Pages）与安卓（Capacitor WebView）共用同一份 Web 产物，存档走 localStorage 两端通用。

## 三、架构分层

```
src/
  main.ts              引擎启动、FIT 缩放、Arcade 物理（零重力）、场景注册
  data/                纯数据层（无副作用，便于调平衡）
    balance.ts           全局常量与数据聚合导出
    zombies.ts           55 类僵尸、8 元素、弱点/抗性/免疫与图鉴数据
    levels.ts            50 关波次配置与确定性关卡生成
    skills.ts            48 技能 + 29 组合技 + 稀有度权重
    shop/equipment.ts    军械库与三槽行为装备
  systems/             纯逻辑层（不继承 Phaser 对象）
    WaveManager.ts       波次状态机：idle→spawning→clearing→idle
    SkillSystem.ts       局内技能等级、稀有度刷新、组合技检测
    MetaUpgrades.ts      局外养成等级→局内初始属性换算
    SaveManager.ts       localStorage 存档（金币/星级/解锁/养成）
  entities/            实体层（继承 Phaser 物理 Sprite/对象池成员）
    Cannon.ts            炮台：玩家控向、按射速自动开火
    Zombie.ts            僵尸：18 种行为原型，preUpdate 内自驱动
    Bullet.ts            子弹/酸球/导弹复用
    Coin.ts              金币掉落与吸附
  scenes/              场景层（Phaser Scene）
    BootScene            纹理程序化生成
    MenuScene            主菜单
    LevelSelectScene     关卡选择 + 永久养成商店
    GameScene            战斗主循环（核心）
    UIScene              叠加 HUD（与 Game 并行运行）
    ResultScene          结算
  ui/helpers.ts        按钮、文本样式、遮罩等 UI 工具
```

**分层原则**：`data` 只管数据、`systems` 只管逻辑、`entities` 只管自身行为、`scenes` 编排一切。`GameScene` 是唯一的「指挥层」，持有各 system 与实体，在 `update()` 里按帧编排，避免实体之间互相耦合。

## 四、核心系统设计

### 4.1 场景流程

```
Boot(生成纹理) → Menu → LevelSelect(选关+商店) → Game + UI(并行) → Result → 回 LevelSelect
```

- `Game` 与 `UI` 双场景并行：`UI` 通过 `scene.get('Game')` 读取公开状态字段（`runCoins`/`wallHp`/`levelName`…）渲染 HUD，战斗与界面解耦。
- `Result` 通过 `scene.start` 传递结算数据（星级、金币、连杀、组合技列表）。

### 4.2 波次系统（WaveManager 状态机）

```
idle ──startNextWave──▶ spawning ──全部刷完──▶ clearing ──场上清空──▶ idle
                                  └─▶ levelDone（已无后续波）
```

- `WaveManager` 每帧由 `GameScene.update` 调用 `update(dt, aliveCount)`，自身不碰 Phaser 对象，只通过 `onSpawn` 回调通知场景生成僵尸。
- 每波由多组 `SpawnGroup` 组成，组内按 `interval` 间隔刷怪、支持 `delay` 错峰，形成「混合怪潮」节奏。
- **波次清空触发**：`state==='idle' && currentWave>0 && alive.length===0` 时进入慢动作过渡，延迟后弹技能选择或结算。此处必须用 `transitioning` 标志立即置位，防止 500ms 窗口内每帧重复调度（曾因此叠加出几十个技能界面、选完后僵尸不暂停的 bug）。

### 4.3 僵尸设计（55 类定义 + 18 种行为原型 + 对象池）

全部继承 `Phaser.Physics.Arcade.Sprite`，池化复用（`maxSize: 200`）。行为集中在 `Zombie.preUpdate` 自驱动，通过回调与场景通信：

| 类型 | 机制 | 关键回调 |
| --- | --- | --- |
| normal/fast/tank | 直线推进触墙攻击 | `onAttackWall` |
| boss | 高血量、周期召唤小怪 | `onSummon` |
| spitter | 远程：进射程停下喷酸 | `onSpit` |
| exploder | 死亡时范围爆炸 | `onExplode` |
| healer | 周期治疗附近僵尸 | `onHeal` |
| shield | 自带能量护盾优先吸伤 | — |
| ghost | 周期隐身（隐身期无敌） | — |
| berserker | 血量越低速度越快（最高 2.8×） | — |
| summoner | 周期召唤 fast 小怪 | `onSummon` |

**死亡流程**：`takeDamage` 返回是否致死 → `killZombie` 触发粒子/金币/连杀/爆弹 → `die()` 播放「膨胀→闪白→缩小」动画 → `recycle()` 归池。`dying` 标志位让 `preUpdate` 在动画期间跳过行为逻辑，避免「尸体」继续攻击/移动。

### 4.4 炮台与操控（手动控向，无自动索敌）

- 炮台方向**完全由玩家控制**：网页鼠标移动（无需按住）、安卓触摸拖动均可瞄准，松手保持最后方向。
- 按射速自动开火（有僵尸时），方向取 `aimAngle`；**不再自动锁定最近僵尸**。
- 设计取舍：把「瞄准」交给玩家增加操作深度，把「开火时机」交给系统避免手忙脚乱；默认朝上 `-π/2`，首次输入前也有合理指向。

### 4.5 技能系统（局内三选一 + 稀有度 + 重铸 + 组合技）

- **48 个技能**分攻击/防御/辅助三类，各有 `rarity`（common/rare/epic/legendary）与 `maxLevel`，其中元素技能直接改变伤害类型或克制倍率。
- **稀有度加权刷新**：`rollChoices(3)` 按权重抽取，`幸运星` 技能把 common 权重转移到高稀有度，鼓励 build。
- **重铸（reroll）**：花金币重新随机三选，多次重铸成本递增，给非酋止损机会。
- **29 个组合技**：满足「多技能最低等级」条件自动激活（如「末日审判」=激光+导弹+爆炸）。UI 上会标注「差一个就激活」的提示，引导玩家凑 build。
- 技能选择期间 `physics.pause()` 暂停物理、`choosingUpgrade` 标志让 `update` 提前返回，确保选技能时战斗完全静止。

### 4.6 战斗打击感

| 手段 | 实现 |
| --- | --- |
| 暴击顿帧 | `hitStop(ms)` 设 `hitStopTimer`，顿帧期间 `update` 跳过游戏逻辑（仅递减计时器） |
| 慢动作 | `applySlowMo(duration, scale)` 设 `slowMoScale`，后续系统用 `effectiveDt = dt * scale` |
| 连击倍率 | 连续命中累加 `hitCombo`，伤害 ×(1 + combo×0.02)，封顶 ×2；2 秒不命中清零 |
| 屏震 | `cameras.main.shake`，暴击/爆炸时触发 |
| 低血红屏 | 墙血 <25% 时屏幕边缘红色渐变 + 脉动，越危急越红 |
| 连杀加成 | 连杀达阈值（5/15/30/50）伤害 +10%~+50%，受击或超时清零 |

### 4.7 局外养成 + 存档

- `SaveManager` 单例管理 localStorage（key `zombie-cannon-save-v1`），存金币/解锁关卡/各关星级/四项养成等级。
- 旧档缺字段时与默认值合并，容忍版本升级。
- `MetaUpgrades` 把养成等级换算成局内初始属性（攻击 +8%/级、攻速 +5%/级、墙血 +15%/级、金币 +10%/级），与局内技能叠加。
- `LevelSelectScene` 内置永久升级商店，`metaUpgradeCost` 按 `baseCost × (level+1)^1.6` 递增。

### 4.8 结算与星级

- 胜利星级按剩余墙血比例：≥70% 三星、≥35% 两星、否则一星；只升不降（取历史最高）。
- 通关奖励 `levelClearReward = (80 + levelId×40) × (1 + (stars-1)×0.25)`，星级越高金币越多。
- 失败只返还一半局内金币，鼓励重试。

## 五、数值平衡思路

- **关卡曲线**：`hpScale` 从 1.0（第1关）线性涨到 5.0（第10关），`speedScale` 从 1.0 涨到 1.3，配合怪物种类递增制造难度梯度。
- **新机制分关引入**：每关引入一种新僵尸（tank→exploder→spitter/healer→shield/boss→ghost→berserker→summoner→混潮→终极Boss），让玩家逐步学习应对。
- **波次节奏**：组内 `interval` 随关数递减（1.4s→0.4s），后期怪潮更密集；`delay` 错峰避免一波内同时刷出。
- **对象池上限**：僵尸 200、子弹 500、金币 100、酸球 60、导弹 40，兼顾性能与场面密度。

## 六、跨平台策略

- **同一份 Web 产物**：`vite build` 输出 `dist/`，GitHub Pages 直接托管；`npm run android:sync` 把同一份产物同步进 Capacitor 安卓工程，两端零分叉。
- **存档通用**：安卓 WebView 同样支持 localStorage，`SaveManager` 无需改动。
- **竖屏锁定**：建议在 `AndroidManifest.xml` 设 `screenOrientation="portrait"`。
- **输入归一**：Phaser 的 pointer 事件对鼠标/触摸统一抽象，`pointermove` 在桌面由悬停触发、在移动端由触摸拖动触发，一套代码两用。

## 七、关键设计决策记录

1. **手动控向替代自动索敌**：原版「按住屏幕手动瞄准、松手自动锁敌」导致操作割裂；改为纯手动控向（鼠标移动/触摸拖动），方向始终由玩家主导，松手保持方向。
2. **波次过渡用 `transitioning` 标志防重入**：`choosingUpgrade` 在延迟回调内才置位，500ms 窗口内波次清空条件每帧重触发会叠加数十个技能界面；新增 `transitioning` 在条件命中时立即置位，确保只调度一次。
3. **技能选择期间 `physics.pause()` + `choosingUpgrade` 双闸**：物理暂停停位移，`update` 提前返回停逻辑，选完 `resumeAfterChoice` 复位两者再开下一波。
4. **死亡动画与行为隔离**：`dying` 标志让 `preUpdate` 跳过行为逻辑，`die()` 内 Tween 仅改 scale/alpha 不改位移，避免「尸体」继续推进或攻击。
5. **零美术依赖**：纹理程序化生成，降低协作门槛，便于先用玩法验证再补美术。
