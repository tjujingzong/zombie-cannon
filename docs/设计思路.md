# 僵尸炮台 · 设计思路

> 当前基线：v1.1.1，更新于 2026-08-19。本文描述当前实现；历史版本的数据请查阅 [迭代记录](迭代记录.md)。

《僵尸炮台》是一款 720 × 1280 竖屏塔防射击游戏。玩家负责瞄准，炮台负责持续开火；敌军压力在波次中快速堆高，玩家通过技能、组合技、过载和装备把压力转化为清屏反馈。

## 一、当前设计基线

| 维度 | v1.1.1 规模 | 设计约束 |
| --- | --- | --- |
| 战役 | 99 关，前 10 关手工编排，后 89 关确定性生成 | 每 5 关 Boss；第 21 关起大部分关卡携带词缀 |
| 敌人生态 | 110 类、18 种基础行为原型、8 种元素、12 类首领 | 数据由 `zombies.ts` 统一定义；对象池复用必须完整重置状态 |
| 局内构筑 | 95 技能、47 组合技、6 条终极路线 | 每项技能必须有真实运行时效果，禁止只展示数值 |
| 敌方变化 | 8 种精英词缀、8 种关卡词缀、首领二阶段 | 颜色、标签、行为和奖励必须保持一致 |
| 局外配置 | 24 永久强化、14 军械、125 种三槽装备组合、6 套伙伴协议 | 装备优先改变行为节奏，不只堆倍率 |
| 长期模式 | 每日挑战、末日无尽、每周行动、成就、挑战契约 | 离线可用、种子可复现、同一结算入口落盘 |
| 资源策略 | 普通敌人与多数图标程序绘制；12 张 Boss 和 6 张终极技能正式位图 | 所有运行时图片必须离线打包并有程序兜底 |

元素伤害统一采用三档倍率：弱点 ×1.55、抗性 ×0.58、免疫 ×0。主炮、灼烧、腐蚀、爆炸、激光、雷电、引力、军械和伙伴都必须经过同一元素结算路径。

## 二、体验目标

1. **单手可操作**：桌面鼠标移动或移动端手指拖动控制方向，松手保持最后角度，有敌人时自动开火。
2. **压力与释放交替**：用密集刷怪、精英组合和关卡词缀制造压力，用过载、组合技、连锁和范围伤害快速释放。
3. **构筑能被看懂**：玩家应能从弹道、元素、辅助单位和 HUD 看出当前路线，而不是只看到伤害数字变大。
4. **失败可复盘**：图鉴明确敌人弱点、免疫、机制和对策；构筑面板显示技能、组合技与主要伤害来源。
5. **离线完整**：Web 与 Android 不依赖远程资源或服务端账号，断网仍能开始、结算、存档和导入导出。

## 三、技术与架构

| 层 | 选型 | 职责 |
| --- | --- | --- |
| 引擎 | Phaser 3.85 | 场景、Arcade 物理、输入、对象池、Tween 与程序纹理 |
| 语言 | TypeScript 5.6 | 数据模型与系统接口约束，构建前执行 `tsc --noEmit` |
| 构建 | Vite 5 | 本地 HMR 和 `dist/` 生产产物 |
| Android | Capacitor 6 | 将同一份 Web 产物打包进 Android WebView |
| 质量检查 | ESLint + Knip | 代码规范和未使用导出检查 |
| 发布 | GitHub Actions | Pages、持续体验 APK 和标签版本 APK |

```text
src/
  main.ts                  Phaser 配置、画布缩放、场景注册
  data/
    balance.ts             全局战斗常量与永久强化定义
    combat.ts              精英词缀、伤害来源、六条构筑路线
    levels.ts              99 关、8 种关卡词缀与确定性生成
    zombies.ts             110 类敌人、元素关系、图鉴与首领表
    skills.ts              95 技能、47 组合技与终极路线
    daily/endless.ts       每日挑战与无尽规则
    equipment/companion.ts 行为装备与 R-7 协议
    operations.ts          每周行动与终身成就
  systems/
    WaveManager.ts         波次状态机和刷怪调度
    SkillSystem.ts         技能等级、刷新、组合技与派生属性
    SaveManager.ts         v1 至 v5 迁移、导入导出、持久化
    MetaUpgrades.ts        局外强化到战斗属性的换算
    BattlefieldEventSystem.ts 战场事件生命周期
    EndlessRunSystem.ts    无尽种子、变异、里程碑与计分
  entities/                Cannon、Zombie、Bullet、Coin
  scenes/                  Boot、Menu、LevelSelect、Codex、Operations、Game、UI、Result
  ui/helpers.ts            通用按钮、文字样式、遮罩与背景
```

分层原则：`data` 只描述规则，`systems` 维护可测试状态，`entities` 管理单体生命周期，`scenes` 负责 Phaser 对象与跨系统编排。`GameScene` 是战斗指挥层；新增独立玩法时优先放入数据或系统，不继续把所有规则塞进场景。

## 四、场景与模式流程

```text
Boot
  -> Menu
     -> LevelSelect -> Game + UI -> Result
     -> Daily       -> Game + UI -> Result
     -> Endless     -> Game + UI -> Result
     -> Codex
     -> Operations
```

- `Game` 与 `UI` 并行运行。HUD 读取战斗场景公开状态，不直接修改实体。
- 普通战役胜利推进关卡并保存星级；每日挑战不会推进战役；无尽按里程碑和最终波次结算。
- 同一随机种子派生出技能、事件、精英、刷怪位置和波次等独立随机流，避免新增一个随机调用改变整局结果。

## 五、关卡与波次

### 5.1 战役生成

- 第 1 至 10 关承担教学和机制首次引入。
- 第 11 至 99 关使用关卡编号作为确定性种子生成场景、波次、敌人池和倍率。
- 每 5 关追加 Boss 终局波；高级章节可出现多个 Boss 和护航单位。
- 第 21 关起有 85% 概率携带关卡词缀；词缀同时影响危险和收益，必须在选关与 HUD 中可见。
- 新敌人在 `firstSeen` 关的首波强制登场，避免只存在于随机池却从未被玩家看见。

### 5.2 WaveManager 状态机

```text
idle -> spawning -> clearing -> idle
                         \-> levelDone
```

`WaveManager` 不创建 Phaser 对象，只通过回调请求 `GameScene` 生成敌人。每个 `SpawnGroup` 指定类型、数量、间隔和延迟。场景使用 `transitioning` 防止清波后的延迟窗口重复创建技能选择或结算界面。

## 六、敌人与元素

### 6.1 数据模型

每类敌人定义：行为原型、元素、弱点、抗性、免疫、生命、速度、触墙伤害、金币、首次出现关、威胁等级、程序纹理、可选正式立绘、机制文案与应对建议。

基础行为覆盖直线推进、快速冲锋、重甲、远程喷吐、治疗、护盾、隐身、狂暴、召唤、自爆、干扰、导体减伤、汲取回复、掘地、跃袭、分裂与首领等 18 类定义。元素、深渊与梦魇单位复用行为骨架，但改变数值、配色和机制组合。

### 6.2 精英与首领

- 精英词缀：疾行、重甲、再生、分裂、爆燃、庇护、战号、适应。
- 精英通过头顶短标签、色彩、光环和实际行为区分；对象回池时必须重置词缀、计时器、护盾、抗性适应和附属对象。
- 首领半血后进入二阶段，提升移动或召唤频率，并触发独立演出。
- 12 类首领全部有正式透明 PNG，并叠加程序光环、王冠和二阶段演出。

## 七、技能与构筑

开局提供 5 次免费选技，选满后敌军规模提高 60%。波次间继续从稀有度加权候选中选择；重铸消耗金币，部分技能会增加候选数量、降低成本或提供免费重铸。

组合技由多个技能的最低等级条件自动激活。六条终极路线是：

| 路线 | 核心玩法 | 终极节点 |
| --- | --- | --- |
| 冰火湮灭 | 冻结聚怪、点燃与爆破连锁 | 元素浩劫 |
| 无限弹幕 | 攻速、多重炮管、穿透与弹射 | 无限弹幕 |
| 天基指挥 | 导弹、空中支援与引力控制 | 轨道指挥 |
| 永恒堡垒 | 护盾、雷区、修复和反伤 | 永恒堡垒 |
| 湮灭阵列 | 玻璃大炮、泰坦重弹与过载 | 湮灭阵列 |
| 钢铁王朝 | 保险复起、防爆闸门与自动维修 | 钢铁王朝 |

六个终极节点全部使用正式位图图标。所有图标都在 `BootScene` 启动阶段完成注册，Android 不访问远程图片。

## 八、战斗反馈与性能

| 反馈 | 作用 |
| --- | --- |
| 暴击顿帧、屏震、慢动作 | 强调关键命中、首领阶段和清波时刻 |
| 连击与连杀 | 奖励持续瞄准和快速清场，HUD 显示倍率与倒计时 |
| 元素色、短标签和光环 | 在高密度场景中识别免疫、精英与支援关系 |
| 伤害来源统计 | 区分主炮、持续伤害、爆炸、导弹、雷电、引力、装备和伙伴贡献 |

对象池用于敌人、子弹、金币和投射物。程序纹理避免为 100 余类普通敌人加载大量位图。性能面板可显示 FPS 低点、活动敌人、投射物、粒子与精英数量，但桌面结果不能替代 Android 真机压力测试。

## 九、局外成长与存档

`SaveManager` 使用 localStorage 键 `zombie-cannon-save-v1`，当前结构版本为 v5，保存：

- 金币、关卡解锁与最高星级；
- 24 项永久强化；
- 军械、三槽行为装备、R-7 协议和挑战契约；
- 每日首胜、无尽纪录、每周行动和终身成就。

加载时按默认值补齐缺失字段，兼容 v1 至 v4。导入会校验格式、版本、金币和关卡字段，失败时恢复原存档。Web 与 Android 共享数据结构但各自拥有 localStorage，不会自动同步；跨端依赖主菜单导出/导入。

任何新增持久化字段都必须：提高结构版本、为旧档提供默认值、验证导入、覆盖重载测试，并在文档中说明迁移结果。

## 十、跨平台与发布

- Vite 输出 `dist/`，GitHub Pages 直接部署。
- `npm run android:sync` 先构建 Web，再同步到 `android/app/src/main/assets/public/`。
- Android 默认版本为 `1.1.1` / `versionCode 2`；CI 体验包以运行号作为递增 `versionCode`。
- 配置发布密钥时，`main` 与 `v*` 标签使用同一 release keystore；否则回退到 debug 证书，不能保证覆盖升级。
- APK 内所有纹理、音频和逻辑均为本地资源，运行时不依赖 CDN。

## 十一、关键设计决策

1. **玩家控向、系统开火**：保留瞄准参与感，同时降低触屏连续点击负担。
2. **普通敌人程序绘制**：100 余类单位共享骨架语言，减少内存、包体和维护成本；正式位图集中给关键首领。
3. **真实元素结算**：图鉴文案必须与伤害入口一致，免疫不能只做视觉标签。
4. **确定性随机拆流**：每日与无尽可复现，系统扩展不会轻易破坏已有种子。
5. **行为装备优先**：装备应改变攻击节奏、投射物或防线反制，不用纯数值层代替玩法。
6. **离线优先**：账号、排行和实时联机在留存验证前不进入核心依赖。

- 所有 `BootScene.preload()` 位图在 Web 与 Android 包内存在。
- 存档导出、导入、旧档迁移和坏数据回退正常。
- APK 版本、签名和 Web 资源对应当前提交。
- 目标 Android 真机完成安装、覆盖升级、战斗帧率、触控与发热测试。
