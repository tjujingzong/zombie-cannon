## 已完成能力

### 核心战斗

- 99 关战役将前 10 关手工教学与后续确定性关卡生成结合，每 5 关安排首领战。
- 第 21 关起引入急速之潮、钢铁尸潮、狂热浪潮、黄金时代、脆弱前线、固守堡垒、超载反应、军械支援 8 种关卡词缀。
- 敌人统一到 `zombies.ts`，元素、弱点、抗性、免疫、首次登场、图鉴和程序纹理共用单一数据源。
- 精英从 4 种扩展到 8 种词缀；首领拥有二阶段；新梦魇单位覆盖终局章节。
- 主炮、持续伤害、爆破、导弹、空中支援、激光、雷电、引力、雷区、辅助炮台、反伤、装备和伙伴统一记录实际伤害。

### 构筑与变化

- 95 个技能与 47 个组合技覆盖攻击、防御、资源和联动；六条终极路线提供明确终局目标。
- 开局 5 次免费选技换取更高尸潮规模，波次间继续强化；稀有度、重铸、免费重铸和候选数量可被技能改变。
- 压力契约允许主动提高下一波数量、速度和精英率，换取稀有保底与金币。
- 补给空投、感染风暴、断电作战、精英猎杀拥有统一进入、计时、进度和清理生命周期。
- 每日挑战与无尽将随机数拆成独立派生流，同一日期或编号可以复现。

### 长期目标

- 24 项永久强化、14 件军械、三槽各 5 件行为装备和 R-7 六套协议全部接入战斗或场景效果。
- 每周行动围绕击杀、波次、过载、组合技、连杀、首领和无尽深度生成目标；终身成就共用职业统计。
- 存档结构升级到 v5，兼容 v1 至 v4；支持导出、导入、未来版本拒绝和坏数据回退。
- Web 与 Android 共用构建和数据结构；Pages 与 APK 均由 GitHub Actions 生成。

### 视觉与资源

- 普通敌人坚持程序绘制骨架与元素色，避免 110 类单位带来不可控的内存和包体成本。
- 6 类早期首领使用正式透明位图，后续 6 类首领程序绘制；4 个早期终极节点使用正式位图，2 个新终极节点程序绘制。
- 关卡卡片、模块列表、图鉴和 HUD 已针对 720 × 1280 与宽屏 FIT 做自适应；终局关卡名会去除重复章节后缀，避免卡片文本串列。

## 下一阶段路线图

### P0：验证而不是继续扩量

1. 在至少一台低端和一台中端 Android 设备记录 100 / 200 / 300 活动敌人下的 FPS 低点、内存、温度与耗电。
2. 为六条终极路线记录出现率、选择率、激活波次、主要伤害占比和通关率。
3. 逐关检查首次出现的免疫单位，确认玩家在失败前能看到弱点提示且有可获得的反制技能。
4. 建立 30 分钟无尽自动跑局，监测对象池残留、重复结算、无敌单位和计时器泄漏。
5. 用同一 release keystore 验证 `android-latest` 连续两个构建可覆盖升级并保留存档。

### P1：表现与可理解性

1. 为基础行为原型补齐轻量出生、受击、死亡动作，不为 110 个定义逐个制作独立逐帧图。
2. 给 10 类场景增加受控的天气和环境音层，先建立低端机关闭开关与粒子预算。
3. 将图鉴、构筑面板和失败结算串成可操作的复盘入口，明确“死于什么、缺少什么克制”。
4. 增加色弱友好的元素符号或形状编码，避免只依赖红绿、蓝紫差异。
5. 用实际触控设备检查所有滚动层、底部导航、技能卡和暂停菜单的点击热区。

### P2：回流与同步

1. 日次与周次数据证明有回流价值后，再引入后端账号和可信时间。
2. 第一项社交能力优先做异步排行榜和成绩分享，不直接进入实时联机。
3. 账号同步必须先定义冲突策略、离线写入和存档回滚，不能简单覆盖本地 v5 数据。
4. 远程配置必须保留离线默认值和版本校验，服务不可用时核心战斗仍能运行。

## 暂不推进

- 不继续以增加普通关卡、技能或敌人数量代替平衡和留存验证。
- 不在核心经济未经长周期测试前加入多货币、装备升品、宝石孔或抽卡。
- 不用强制广告打断波次、过载或结算节奏。
- 不在本地单局性能和种子复现稳定前投入实时双人守城。
- 不把全部程序敌人替换为 AI 位图；这会破坏视觉一致性、包体和同屏性能预算。

## 数据指标

| 指标 | 目标 | 决策用途 |
| --- | --- | --- |
| 首局完成率 | ≥ 70% | 判断教学、初始强度和失败提示 |
| 第三关到达率 | ≥ 55% | 判断前期构筑是否足够吸引 |
| 单局组合技触发率 | ≥ 80% | 判断候选池是否能形成构筑 |
| 六路线使用占比 | 任一路线 ≤ 35% | 发现唯一最优解或过窄前置 |
| 终局波活动敌人 | 180–320 | 保证尸潮观感并控制对象池压力 |
| 桌面中位帧率 | ≥ 55 FPS | 回归基线，不替代移动端验证 |
| 移动端中位帧率 | ≥ 30 FPS | 决定粒子、动画和同屏预算 |
| 每日挑战重复参与率 | ≥ 25% | 判断是否值得投入排行榜 |
| 存档导入成功率 | ≥ 99% | 保障跨浏览器和卸载前迁移 |

## 决策门槛

- P0 真机性能和六路线平衡达标后，才扩大动画与天气预算。
- 每日、无尽和行动档案证明回流价值后，才投入账号与排行榜。
- 正式签名覆盖安装稳定后，才把体验包作为持续更新渠道宣传。
- 实时联机最后评估，不挤占离线核心循环、可读性和性能工作。
